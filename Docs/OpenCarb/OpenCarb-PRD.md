# OpenCarb PRD

## 1. 文档目的

本文定义 `OpenCarb` 的首版产品需求。`OpenCarb` 定位为基于 `OpenClaw` 构建的企业团队级 AI 助理平台，服务对象是企业内部的部门、项目组和工作组，而不是个人用户。产品首期聚焦研发协作场景，优先解决内网模型接入、知识检索、技能治理、安全审计和团队工作区管理。

## 2. 背景与问题

企业在落地 AI 助理时通常会遇到四类阻碍：

- 公有云模型带来的数据外发与合规风险。
- 个人型 AI 工具缺乏团队工作区、统一知识边界和共享治理能力。
- 代码与文档检索割裂，导致 AI 输出无法稳定贴合企业内部实践。
- 开放工具和技能扩展缺乏审计、审批和权限控制，难以通过安全审查。

`OpenClaw` 已经具备本地优先、ACP 桥接、skills 机制和可扩展 agent runtime 等基础能力，适合作为 `OpenCarb` 的执行内核，但企业采购需要的核心是控制面能力：谁能用、能连什么模型、能访问什么知识、哪些技能可启用、发生了什么行为、如何审计和追责。

## 3. 产品定位

### 3.1 一句话定位

`OpenCarb` 是一个面向企业团队的 AI 助理平台，基于 `OpenClaw` 提供的 agent 能力，增加企业级的模型治理、技能治理、安全审计和团队协作控制面。

### 3.2 目标用户

- 研发团队：代码问答、内部 API 调用指导、重构与评审辅助。
- 测试与质量团队：PR 拦截、质量检查、变更风险提示。
- 平台工程团队：知识入口统一、模板和技能治理。
- 技术管理者：成本、采纳率、风险命中率和团队使用情况分析。

### 3.3 购买与部署单元

- 最小购买单元：部门、工作组或项目团队。
- 最小部署单元：一个团队工作区，可绑定多个代码仓、文档源和模型策略。

## 4. 产品目标

### 4.1 V1 业务目标

- 在一个试点团队内验证 AI 助理对研发协作效率的提升。
- 证明内网模型优先的部署方式可以满足基础问答和评审场景。
- 建立从请求接入到审计追踪的最小治理闭环。
- 建立最小审批闭环，先覆盖高风险技能启用和受控外部模型外发两类场景。

### 4.2 V1 用户价值目标

- 团队成员可以在 IDE 入口发起面向企业知识库的问答，管理员可以在 Web 管理台完成配置和审计查询。
- 团队成员可以获得基于内部代码和文档的可靠建议，而不是通用模型幻觉。
- 管理员可以看到谁在用、调用了什么模型、触发了哪些技能、发生了哪些敏感外发。
- 安全或平台管理员可以禁用高风险技能、限制模型出口并回溯关键操作。

## 5. 非目标

以下内容不纳入 V1：

- 面向全公司的统一知识大脑。
- 通用办公自动化和个人生活助理能力。
- 复杂多智能体自治编排。
- 高度定制的行业工作流连接器。
- 全量知识图谱与复杂 Graph DB 依赖分析。

## 6. 试点场景与试点团队建议

### 6.1 推荐试点团队画像

建议选择一个 8 到 20 人的研发工作组作为首个试点对象，特征如下：

- 有稳定的 Git 仓库与基本工程规范。
- 有内部文档沉淀，但新人熟悉系统成本高。
- 对代码评审质量、知识传承、内网合规有明确痛点。
- 能接受一到两个入口先行落地，例如 IDE 插件和 Web 管理台。

### 6.2 推荐首批试点场景

优先只验证三个场景：

1. 企业代码库问答与内部 API 调用指导。
2. PR 评审与安全/规范拦截。
3. 新人 onboarding 与团队文档问答。

### 6.3 暂不纳入试点的场景

- 全自动修复并提交代码到主干。
- 跨多个部门的大规模知识共享。
- 直接接入高敏感生产系统做自动变更。

## 7. 用户角色

### 7.1 团队成员

- 在 IDE 入口发起请求，或通过受管 PR 入口触发 review 场景。
- 访问所在工作区允许的知识、模型和技能。

### 7.2 工作区管理员

- 配置知识源、模型路由策略、技能启停和审批规则。
- 查看工作区的审计与使用统计。

### 7.3 安全/平台管理员

- 配置敏感内容外发规则、可用工具白名单和默认审批策略。
- 介入高风险技能安装和高敏感请求审批。

### 7.4 最小身份与权限模型

- 身份源统一来自企业 IdP 或内部账号系统。
- `PlatformAdmin` 负责平台级安全基线、模型出口和默认策略。
- `SecurityAdmin` 负责高风险审批与审计复核。
- `WorkspaceAdmin` 负责工作区成员、知识源、技能启停和工作区策略。
- `WorkspaceMember` 负责在获准入口中使用问答、review 和知识能力。

## 8. 核心需求

### 8.1 团队工作区

- 支持创建工作区并绑定成员、仓库、文档集和模型策略。
- 工作区之间的知识、审计和技能配置默认隔离。

### 8.2 模型接入与路由

- 支持内网模型服务接入，作为默认首选推理源。
- 支持外部模型 API 作为显式启用的补充或回退通道。
- 支持基于任务类型、敏感级别、成本阈值选择模型部署。

### 8.3 知识索引

- 接入 Git 仓库、文档库和 FAQ。
- 支持增量更新、权限继承和最小可见范围控制。
- 权限过滤由 `OpenCarb Knowledge Service` 在检索前后统一执行，而不是由 runtime 自行判断。

### 8.4 技能治理

- 兼容 `OpenClaw`/AgentSkills 目录式 skill 结构。
- 支持工作区级启用、禁用、审批和版本锁定。
- 支持区分官方技能、团队私有技能和第三方导入技能。

### 8.5 审计与策略

- 对 prompt、工具调用、模型请求、文件访问和技能执行进行留痕。
- 对敏感内容外发、风险工具调用和高风险技能安装做策略评估。
- 审计记录支持按用户、时间、工作区、模型和技能检索。

### 8.6 最小审批闭环

- V1 只覆盖两类审批：高风险技能首次启用、受限内容外发到外部模型。
- 审批由 `Policy Engine` 触发，转入 `Job Orchestrator` 的挂起任务。
- IDE 同步会话遇到审批时返回 `pending approval` 状态和审批单号，不在前台会话中阻塞等待。
- Web 管理台负责展示审批状态、审批结果和恢复后的任务结果。

### 8.7 管理台

- 显示工作区配置、模型接入状态、技能启停状态。
- 显示调用量、失败率、成本和审计事件摘要。

## 9. 用户旅程

### 9.1 代码问答

1. 开发者在 IDE 里提出关于内部模块的实现问题。
2. `OpenCarb` 读取当前工作区上下文，调用知识索引获取相关代码与文档。
3. 策略层判断请求是否可以在内网模型上直接执行。
4. Agent runtime 生成回答，并在响应中标明参考来源。
5. 系统记录模型、技能、工具和检索行为。

### 9.2 PR 拦截

1. 代码仓触发 PR review webhook。
2. 平台调用指定工作区的 review 模板和技能集。
3. 模型在代码变更、规范规则和安全策略基础上给出风险意见。
4. 命中高风险规则时，平台把结果写入 PR 并记录审计日志。

## 10. 成功指标

### 10.1 业务指标

- 试点团队周活跃使用率不低于 60%。
- 试点团队续用意愿达到 70% 以上的正向反馈。
- 代码问答命中率与用户满意度达到内部问卷约定阈值，建议首轮目标不低于 70%。

### 10.2 平台指标

- 知识检索命中率不低于 70%。
- 内网模型命中比例不低于 80%。
- 审计事件完整率不低于 95%。
- 高风险技能审批和外发审批必须可回溯到审批人和审批结果。
- 平均响应时延控制在团队可接受范围内，建议首轮目标为问答场景 15 秒内。

## 11. 非功能需求

- 默认支持私有化或内网部署。
- 所有关键链路具备可观测性与错误追踪能力。
- 工作区配置变更必须可审计。
- 高风险行为必须支持审批或强制拦截。

## 12. 版本结论

V1 的关键不是做出“最强 agent”，而是做出一个企业团队愿意试点的、边界清晰的 AI 平台最小闭环：工作区、模型接入、知识检索、技能治理、审计策略和基础管理台。
