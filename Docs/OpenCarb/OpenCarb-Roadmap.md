# OpenCarb 路线图

## 1. 目标

本路线图用于把 `OpenCarb` 从规划阶段推进到试点交付，再推进到可复制的企业产品。路线设计遵循一个原则：先证明单团队价值，再扩展治理与生态，而不是一开始做成大而全平台。

## 2. 阶段概览

| 阶段 | 时间建议 | 目标 | 主要产出 |
| --- | --- | --- | --- |
| Phase 0 | 2-4 周 | 明确试点与 V1 范围 | PRD、架构说明、试点方案 |
| Phase 1 | 4-8 周 | 建立最小技术闭环 | 工作区、模型接入、知识索引、审计、轻量 PR review、最小审批 |
| Phase 2 | 6-10 周 | 企业化增强 | 通用审批、增强技能治理、可观测性、异步任务 |
| Phase 3 | 8-12 周 | 规模化复制 | 模板化部署、私有技能仓、跨团队复用 |

## 3. Phase 0：产品验证

### 目标

- 选定试点团队。
- 收敛 V1 场景与不做项。
- 明确部署模式和安全边界。

### 必交付

- `OpenCarb PRD`
- `OpenCarb V1 范围清单`
- `OpenCarb 系统架构说明`
- `OpenCarb 部署与安全边界设计`

### 验收标准

- 试点团队和目标场景被确认。
- 内网模型接入方式和外发策略被确认。
- 企业版与 `OpenClaw` 的分层边界被确认。

## 4. Phase 1：最小可用版本

### 目标

构建一个部门级团队愿意试用的最小闭环。

### 范围

- 工作区创建与成员管理。
- IDE 入口和 Web 管理台。
- 内网模型接入和一个外部模型回退通道。
- Git 仓库和文档索引。
- 基础技能启停与工作区级版本锁定。
- 审计日志最小闭环。
- 轻量 PR review webhook/bot。
- 两类最小审批：高风险技能启用、受限内容外发。

### 核心里程碑

1. 完成工作区与会话映射。
2. 完成模型代理和基础路由。
3. 完成知识索引和问答链路。
4. 完成审计记录链路与审批挂起恢复机制。
5. 在试点团队中启用 IDE 入口、Web 管理台和轻量 PR review。

### Phase 1 验收标准

- 代码问答和文档问答可用。
- 新人 onboarding 问答可基于团队知识源返回带来源的答案。
- 至少一个真实仓库的 PR review 轻量闭环可用。
- 至少一个审计页面可以回溯请求。
- 管理员可控制技能可见性和模型出口。
- 高风险技能启用和受限外发请求可进入挂起审批并在审批后恢复。

## 5. Phase 2：企业化增强

### 目标

补齐企业采购真正关心的治理能力。

### 范围

- 通用审批流。
- 技能审批、灰度发布和多环境治理。
- 异步任务与后台作业。
- 质量与成本指标看板。
- 更完整的 PR review 集成。

### 核心里程碑

1. 技能治理模型上线。
2. 通用审批与高风险任务拦截上线。
3. 异步索引与 review 作业上线。
4. 使用指标与成本指标可视化。

### Phase 2 验收标准

- 第三方技能不再是“安装即用”，而是“治理后可用”。
- 高风险外发与高风险工具调用可审批。
- 管理员能看见成本和采纳趋势。

## 6. Phase 3：规模化复制

### 目标

让产品可以从一个试点团队复制到多个团队和多个场景。

### 范围

- 标准部署模板。
- 团队模板和默认策略包。
- 企业私有技能仓。
- 跨团队能力复用。

### 核心里程碑

1. 形成标准化部署文档。
2. 形成团队模板与默认策略。
3. 形成技能发布和审核流程。

### Phase 3 验收标准

- 新团队可以在标准模板上快速开通工作区。
- 技能与策略可复用而不需要重复配置。
- 产品具备从单团队走向多团队部署的基础。

## 7. 资源投入建议

### 最小团队配置

- 产品/项目负责人 1 人。
- 全栈或平台工程师 1-2 人。
- AI/后端工程师 1-2 人。
- 前端工程师 1 人。
- 安全/平台支持 0.5-1 人。

### 优先级建议

优先把工程投入放在：

- 工作区与控制面。
- 模型代理与安全边界。
- 知识索引与检索质量。
- 审计与治理闭环。

不要优先放在：

- 花哨的多智能体编排。
- 复杂自动化工作流广泛扩张。
- 过重的行业定制。

## 8. 风险与阶段性应对

| 风险 | 最容易出现的阶段 | 应对 |
| --- | --- | --- |
| 范围膨胀 | Phase 0-1 | 严格限制核心场景数量 |
| 内网模型效果不足 | Phase 1 | 保留受控外部模型回退 |
| 上游变更影响适配 | Phase 1-2 | 保持适配层稳定边界 |
| 安全质疑导致试点停滞 | Phase 1-2 | 优先交付审计与审批能力 |
| 扩展时运维复杂度陡增 | Phase 3 | 模板化与标准化部署 |

## 9. 决策建议

如果资源有限，最推荐的执行顺序是：

1. 先完成 `Phase 0` 文档与试点确认。
2. 再完成 `Phase 1` 的最小问答与审计闭环。
3. 只有当试点团队形成正反馈后，再进入审批、技能仓和多团队复制。

## 10. Phase 2 签收与进入 Phase 3 准入条件

Phase 2 开发已完成，进入签收/运营窗口。进入 Phase 3 前需满足：

1. **签收闭环**：Phase 2 关闭评审（`OpenCarb-Phase2-Closeout-Review.md`）已获产品/技术签收。
2. **回归可用**：执行 `npm run smoke:phase2`（需先启动 control-plane）可重复通过。
3. **交付物齐备**：Phase 3 启动包（Backlog、接口契约、验收标准、RACI/DRI）已产出或已排期。

详见 `OpenCarb-Phase2-Closeout-Review.md` 第 4 节。

## 11. 结论

`OpenCarb` 的路线图应坚持“小范围试点、强治理优先、渐进扩展”的策略。产品价值会先体现在单团队的知识问答、代码评审和新人 onboarding 上，然后再逐步扩展到技能生态和更复杂的企业工作流。
