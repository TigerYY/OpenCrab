# opencrabmvp 信息架构重规划说明

## 1. 章节唯一职责与边界（roadmap / readiness / progress）

### roadmap（产品路线图）

- **唯一职责**：表达「未来规划」——各 Phase 的目标、能力域、进入条件，不承担当前交付状态或历史执行细节。
- **边界**：仅描述 Phase 0–7 的「是什么」「做什么」「何时可进入」；不列举具体任务、负责人、完成时间。
- **禁止**：在路线图内写「E1/E2/E3 已交付」「可签收」等当前状态；不重复「开发准备包 4/4 已完成」等 readiness 内容。

### readiness（开发准备完成度）

- **唯一职责**：表达「进入开发前的准备是否就绪」——Phase 1/2 准备包完成度、当前结论一句。
- **边界**：准备包清单 + 一句当前结论；不展开 Phase 目标、不重复路线图时间线。
- **禁止**：不写 Phase 3 交付细节；不与 progress 表重复「已完成」任务。

### progress（开发进展 → 交付看板）

- **唯一职责**：表达「当前交付状态」——已交付项、进行中、下一步；与路线图建立引用关系（来源：Roadmap Phase X）。
- **边界**：以 Epic/里程碑或任务模块为行，状态 + 负责人；不重复 Phase 目标长文案。
- **禁止**：不在此处定义「Phase 目标」；不与 roadmap 对同一 Phase 给出矛盾状态。

|--------|----------|------------|-------------------|

## 3. 状态口径规则与映射

### 状态枚举及含义

| 状态 | 含义 | 使用场景 |
|------|------|----------|
| 已完成 | 该阶段或该任务已做完并验收 | Phase 0/1/2；具体任务行 |
| 可签收 | 当前阶段交付完成，待业务/平台签收后可进入下一阶段 | Phase 3 |
| 进行中 | 当前阶段尚未收口或任务进行中 | 仅当确实未完成时使用 |
| 规划中 | 未来阶段，依赖前序签收 | Phase 4–7 |

### 判定规则

- Phase 3：若文案为「E3 已交付，Phase 3 彻底完成，可签收」→ 状态徽标应为 **可签收**（或「已交付」），不得为「进行中」。
- 同一 Phase 在 roadmap 与 progress 中状态一致：若 roadmap 写「可签收」，progress 表对应行不写「进行中」。

### 现有内容映射

- **roadmap Phase 3 卡片**：保留「收口完成，可签收」；可加标签「可签收」。
- **progress 表 Phase 3 行**：任务内容保持「E1/E2/E3 技能仓/E4 已交付…」；状态列由「进行中」改为「可签收」或「已交付」。
- **readiness 当前结论**：保留一句，与执行总览一致，不重复长段。

### 实施顺序

1. **结构**：在 `roadmap` 前新增 `id="summary"` 的「执行总览」section；调整 nav 增加「执行总览」、将「当前进度」改为「交付看板」；`readiness` 标题改为「开发准备与历史」。

3. **标签**：progress 表 Phase 3 行状态列改为「可签收」或「已交付」；检查 roadmap 与 progress 无状态冲突。
