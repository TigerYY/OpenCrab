# OpenCrab V1 范围清单

## 1. V1 范围原则

- 只服务一个团队工作区，不追求全公司级统一平台。
- 只打通 2 到 3 个高价值场景，不追求无边界泛化。
- 默认内网模型优先，外部模型 API 仅作为受控补充。
- 优先建设治理闭环，而不是堆叠高级 agent 能力。

## 2. 试点建议

### 2.1 试点对象

- 一个 8 到 20 人的研发工作组。
- 至少拥有 2 个活跃代码仓和 1 套内部文档来源。
- 有明确的代码评审、知识问答或新人 onboarding 痛点。

### 2.2 试点周期

- 准备期：2 周。
- 首轮上线与验证：4 到 6 周。
- 复盘和范围调整：2 周。

## 3. V1 必做清单

### 3.1 入口层

- IDE 入口，支持团队问答与代码上下文请求。
- Web 管理台，支持工作区配置与审计查询。
- V1 不要求面向团队成员的通用 Web Chat，Web 侧以管理和审计为主。

### 3.2 工作区与身份

- 创建工作区。
- 添加成员与角色。
- 绑定仓库、文档集和模型策略。

### 3.3 模型层

- 接入 1 种内网模型网关。
- 接入 1 种外部模型 API。
- 支持基础任务路由策略。

### 3.4 知识层

- Git 仓库索引。
- 文档库或 FAQ 索引。
- 增量更新与基本权限继承。

### 3.5 技能层

- 兼容 `OpenClaw` skills 目录与 `SKILL.md` 规范。
- 工作区级启用、禁用。
- 高风险技能需审批后启用。
- 支持工作区级版本锁定。
- 技能最终可见列表由平台预计算下发给 runtime，runtime 不直接扫描全部已安装技能。

### 3.6 安全与审计

- 记录 prompt、模型、工具、技能、文件访问、外发行为。
- 提供敏感内容外发拦截。
- 提供工具白名单和模型出口限制。
- V1 最小审批范围只覆盖高风险技能启用和受限内容外发，不做通用审批编排。

### 3.7 管理台

- 工作区配置页。
- 模型接入页。
- 技能治理页。
- 审计日志页。
- 基础指标页。

## 4. V1 核心场景

### 场景 A：企业代码库问答

- 用户能基于团队仓库和文档获得带来源的回答。
- 回答优先在内网模型完成。

### 场景 B：PR 评审与拦截

- 支持对 PR 变更做规范和安全层面的初筛。
- V1 允许先以轻量 webhook/bot 方式落地，不要求完整平台化 review 流程。
- 结果可写回代码托管平台或管理台。

### 场景 C：新人 onboarding

- 用户可以围绕系统模块、目录结构和内部流程提问。
- 回答可关联代码与文档来源。

## 5. V1 明确不做

- 跨团队知识共享市场。
- 多节点沙箱执行集群。
- Agent 自治编排平台。
- 行业级复杂工作流连接器。
- Graph DB 驱动的全局依赖图谱。
- 大规模第三方技能自由安装。

## 6. V1.5 候选项

- Git 平台深度集成。
- 团队级 prompt 与 policy 模板。
- 企业私有技能仓。
- 异步 agent 作业与定时任务。
- 质量与采纳率看板。

## 7. 验收标准

### 产品验收

- 一个工作区可以独立完成创建、配置和成员接入。
- 代码问答和新人 onboarding 两个场景必须稳定可用。
- PR review 需在试点团队中跑通至少一个真实仓库的轻量闭环。
- 管理员可启停技能并查看审计记录。

### 技术验收

- 请求能在内网模型与外部模型之间按策略路由。
- Git 和文档索引可进行初始构建与增量更新。
- 审计链路完整覆盖模型、工具和技能执行。
- 审批触发的任务可进入挂起状态，并能在审批后恢复执行或终止。
- 检索权限必须由平台服务统一过滤，不允许 runtime 跨工作区直接拼接原始知识源。

### 业务验收

- 试点团队周活跃率不低于 60%。
- 代码问答满意度建议不低于 70%。
- 内网模型命中比例不低于 80%。
- 代码问答与 review 场景有明确使用反馈。
- 安全审查可接受当前外发与审计策略。

## 8. 退出条件

出现以下任一情况时，V1 范围需收缩或延期：

- 内网模型效果无法支撑核心问答场景。
- 审计链路不完整，无法满足试点合规要求。
- 工作区、技能或模型策略无法隔离，存在明显越权风险。
