# OpenCrab Phase 5 执行 Backlog

## 1. 文档目的

本文为 Phase 5 质量闭环与采纳增长的可执行看板骨架。进入条件与目标以 [OpenCrab-Roadmap](OpenCrab-Roadmap.md) 第 8 节为准；待 Phase 4 签收或团队复制与轻治理核心就绪后，可在此 Backlog 中细化 Epic、Story、DoD 与依赖。

## 2. Phase 5 总目标

- **最小评测基线**：面向 2–3 个核心场景的评测基线，支撑「有没有效果、值不值得扩」的判断。
- **工作区级可见性**：工作区级使用、命中率、满意度、成本可见性。
- **轻量回溯与反馈**：Prompt/模板/技能版本轻量回溯；失败样本回流、人工标注入口、低成本复盘报表。

## 4. 非目标（Phase 5 不做）

- A/B 平台化、安全红队、组织级运营中台、正式 showback/chargeback（归属 Phase 7 或后续）。
- 多租户计费与用量计费（归属 Phase 7）。
- 跨区域/多集群部署（归属 Phase 7）。

## 5. 验收与退出条件

- 管理员能基于工作区级数据判断效果与成本趋势。
- 支持失败样本与反馈的轻量回流与复盘。

## 6. 下一步

- 进入 Phase 5 前，需完成 Phase 4 签收或团队复制与轻治理核心交付。
- 与试点或技术管理方确认效果与成本可见性需求后，将本 Backlog 中的 Story 细化并排期。
