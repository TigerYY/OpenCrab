# OpenCrab 变更检查清单

提交代码或合并前，请按本清单做最小质量与一致性检查。与 `OpenCrab-Engineering-Playbook.md`、`AGENTS.md` 配合使用。

---

## 1. 提交前最小检查项

在本地执行并确认通过后再提交：

| 检查项 | 命令或动作 | 说明 |
|--------|------------|------|
| 构建 | `npm run build` | 根目录执行；控制面与 web-console 均需构建成功 |
| 测试 | `npm run test` | 控制面单测/集成测通过 |
| 冒烟（若影响） | `npm run smoke:phase1` 或 `npm run smoke:phase2` | 仅当本次改动可能影响现有 smoke 时必跑；若未跑，须在 PR 说明中注明原因及替代验证方式 |
| 文档同步（若触发） | 见下节 | 接口、阶段、能力边界变更时须更新或确认相关文档 |

CI（`.github/workflows/ci.yml`）已对 push/PR 到 main 执行 `npm ci`、`build`、`test` 及 phase2-smoke；本地提交前建议至少跑通 `build` 与 `test`，避免直接依赖 CI 才发现问题。

---

## 2. 文档变更触发条件

以下情况**必须**在同一变更集中更新或确认文档，避免实现与文档脱节：

- **新增或修改对外 API**：在对应 Phase 的 `OpenCrab-PhaseN-Interface-Contract-Pack.md`（或文档中声明的接口列表）中补充/更新路径、方法、请求响应与错误码。
- **变更阶段状态或验收结论**：更新 `README.md` 的“当前阶段”、或对应 Phase 的 Closeout-Review / 验收包，使“已完成/进行中/规划中”与事实一致。
- **变更产品范围或能力边界**：若涉及 PRD、V1-Scope、Roadmap 的实质性表述，按 `AGENTS.md` 须人工确认后再改，并在此变更中一并提交文档修改。
- **变更部署或运行方式**：更新 `OpenCrab-Deployment-Template.md` 或 Runbook 中相关步骤与环境要求。
- **仅文案/样式/配置默认值**：可不更新设计文档，但若用户可见行为变化，建议在 PR 说明中简述。

## 3. PR / 变更说明模板

提交 PR 或撰写 commit 说明时，建议包含以下信息，便于审查与回溯：

```text
## 目的
（一句话说明本变更要解决的问题或要达成的结果）

## 影响面
（涉及哪些模块/接口/页面/文档；是否影响部署或配置）

## 验证方式
（如何验证：如已跑 test/smoke、手工步骤、或指向任务卡中的验证方法）

## 回滚方式
（若合并后出问题如何回退：如 revert 本 PR、还原某配置、或指向 Runbook 步骤）
```

可选：若使用任务卡，可附上任务卡链接或粘贴“目标、边界、DoD、验证方法、回滚方式”摘要。

---

## 4. 代码、文档、测试联动规则（摘要）

- **先定契约再写实现**：接口或行为变更时，先更新或确认契约/文档，再改代码与测试。
- **实现与测试同改**：修改后端逻辑或 API 时，同步补充或修改测试；提交前 `npm run test` 通过。
- **文档与实现同提交**：凡触发“文档变更条件”的改动，文档更新与代码放在同一 PR/变更集中，避免只改代码不改文档。
- **回滚一致性**：回滚代码时，若有对应文档修改，须一并回滚，保持文档与代码版本一致。
