# Phase 4+ 能力分类：部门级必需 vs 可后移企业能力

本文档对原 Phase 4-7 所涉能力按「部门级/工作组级最小可体验」与「可延后至企业扩展阶段」进行分类，用于后续路线图重构依据。目标客户为部门级、工作组级用户；组织形态偏扁平化，优先「多工作区自治 + 轻中心治理」。

## 原 Phase 4：组织级治理

| 能力 | 分类 | 说明 |
|------|------|------|
| SSO/IdP 最小接入（OIDC/SAML 任选其一） | 部门级必需 | 企业账号登录，满足试点准入；不做复杂 SCIM |
| 组织身份接入（SCIM 或等价同步） | 后移 | 多部门大规模统一同步，延后至企业扩展包 |
| 组织级权限与策略（跨工作区角色与策略继承） | 后移 | 重型组织树与继承，延后 |
| 组织-工作区映射（复杂层级） | 后移 | 扁平化下先做「工作区↔成员」即可 |
| 数据分级、保留策略与合规策略 | 部分必需 | 仅保留「基础保留策略、审计留痕」；正式数据分级体系后移 |
| 密钥/数据治理（KMS、BYOK） | 后移 | 延后至企业扩展包 |

## 原 Phase 5：运营与质量平台

| 能力 | 分类 | 说明 |
|------|------|------|
| 面向 2–3 个核心场景的最小评测基线 | 部门级必需 | 让团队知道「有没有效果、值不值得扩」 |
| 工作区级使用/命中率/满意度/成本可见性 | 部门级必需 | 工作区级即可，不做组织级运营中台 |
| Prompt/模板/技能版本的轻量回溯 | 部门级必需 | 低成本复盘与回溯 |
| 反馈闭环（失败样本回流、人工标注入口） | 部门级必需 | 支撑采纳增长 |
| 评测体系与效果基线（eval、基准集、A/B）中的 A/B 平台化 | 后移 | 延后 |
| 效果治理（安全红队或等效） | 后移 | 延后 |
| 成本归因与 showback/chargeback 正式化 | 后移 | 先做可见性，正式分摊/出账后移 |
| 组织级运营分析与告警闭环 | 后移 | 延后至企业扩展包 |

## 原 Phase 6：企业入口与生态扩展

| 能力 | 分类 | 说明 |
|------|------|------|
| 跨团队共享的知识包/技能包/模板目录 | 部门级必需 | 偏扁平协作，先做共享与复用 |
| 协作审批与交接（部门内、部门间） | 部门级必需 | 轻量协作，不先做复杂组织树 |
| 一个真实高频入口或连接器深化（如飞书/Slack 或 Jira 其一） | 部门级必需 | 由真实需求拉动，不并行铺开多入口 |
| 企业 IM/聊天入口、2–3 类新连接器并行 | 后移 | 收敛为「单点突破」再扩展 |
| 流程入口统一与编排基础（重型） | 后移 | 延后 |

## 原 Phase 7：平台化与商业基础

| 能力 | 分类 | 说明 |
|------|------|------|
| 多租户运营与配额管理 | 后移 | 多部门稳定复用后再做 |
| 计费/分摊与 showback/chargeback 深化 | 后移 | 延后 |
| HA、备份恢复、容灾与多集群/多地域 | 后移 | 企业扩展包 |
| 生态市场基础（技能/策略发布、审核、内部分发） | 后移 | 当前已有技能仓与策略包；完整市场机制后移 |

## 小结

- **部门级必需**：SSO-lite、工作区/策略/技能/知识模板与复制、轻治理（审计留痕、基础保留、基础角色）、最小评测与工作区级成本/采纳可见性、单点入口或连接器、跨团队共享与协作。
- **可后移企业能力**：SCIM、组织级策略继承、数据分级体系、KMS/BYOK、A/B 与红队、组织级运营中台、正式 showback/chargeback、多入口并行、重型流程编排、多租户、计费、HA/多地域、完整生态市场。

以上分类已用于 [OpenCrab-Roadmap](OpenCrab-Roadmap.md) 与 [OpenCrab-Longterm-Roadmap](OpenCrab-Longterm-Roadmap.md) 的 Phase 4–7 重构。
