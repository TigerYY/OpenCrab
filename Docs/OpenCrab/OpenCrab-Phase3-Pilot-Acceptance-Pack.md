# OpenCrab Phase 3 Pilot Acceptance Pack

## 1. 文档目的

本文定义 Phase 3 规模化复制的验收包，供产品、技术、平台与试点团队签收。范围覆盖：新团队快速开通、模板与策略复用、技能仓引入。

## 2. 验收角色

| 角色 | 职责 |
|------|------|
| PM | 组织验收、汇总结论与优先级 |
| Tech Lead | 技术实现与接口契约签收 |
| Platform | 部署模板与运维流程签收 |
| Pilot Admin | 新团队管理员，验证“从模板创建”与日常配置 |

## 3. 进入条件

- Phase 2 关闭评审已签收，Phase 3 准入条件已满足。
- 至少 1 个现有工作区可作为“模板来源”或“参考配置”。

## 4. 场景 A：从模板创建新工作区

| 编号 | 步骤 | 预期结果 |
|------|------|----------|
| T-01 | 选择已发布的团队模板 | 可查看模板包含的策略与技能集摘要 |
| T-02 | 使用模板创建新工作区，输入名称与可选覆盖项 | 工作区创建成功，审批策略/模型策略/技能集与模板一致或按覆盖项调整 |
| T-03 | 新工作区绑定知识源与 PR 配置 | 与现有 Phase 2 能力一致，无需重新从零配置策略 |

### 验收标准

- 新团队在 1 个工作日内可完成“模板创建工作区 + 绑定仓库/文档 + 启用技能”。
- 策略与技能集可复用，重复配置项显著减少。

## 5. 场景 B：策略包导出与导入

| 编号 | 步骤 | 预期结果 |
|------|------|----------|
| P-01 | 从工作区 A 导出审批策略包 | 获得可版本管理的 JSON 文件 |
| P-02 | 将策略包导入工作区 B | 工作区 B 出现与 A 一致的策略配置（可编辑） |
| P-03 | 导入后修改与审计 | 修改可追溯，与 Phase 2 审计能力一致 |

### 验收标准

- 导出/导入闭环无数据丢失，策略 ID 冲突时有明确处理规则（如覆盖或重命名）。

## 6. 场景 C：技能仓到工作区

| 编号 | 步骤 | 预期结果 |
|------|------|----------|
| S-01 | 在技能仓中浏览已发布技能包及版本 | 可查看版本列表与说明 |
| S-02 | 将技能仓某版本“引入”到指定工作区 | 工作区技能列表中出现该包，进入现有审核/批准流程 |
| S-03 | 多工作区引用同一技能仓版本 | 各工作区独立审批与发布状态，但来源版本可追溯 |

### 验收标准

- 技能仓与 Phase 2 技能治理流程打通，引入后需经工作区级审核/批准方可使用。
- 版本可追溯，支持回滚与灰度策略。

## 7. 场景 D：标准部署与就绪

| 编号 | 步骤 | 预期结果 |
|------|------|----------|
| D-01 | 按部署文档执行 Compose 或脚本 | 控制面、管理台、DB、Redis 按顺序就绪 |
| D-02 | 健康检查与依赖顺序 | 无“未就绪即接收流量”导致的启动失败 |
| D-03 | 新环境首次登录与工作区创建 | 与现有 Phase 2 管理台体验一致 |

### 验收标准

- 部署文档与脚本经平台评审，新环境可在 2 小时内完成部署与首次验证。

## 8. 签收条件

- 上述四类场景均通过验收或已明确例外与后续迭代。
- 部署模板与运营手册已归档，RACI 与 DRI 已落位（见 Phase 3 Timeline RACI）。
