项目说明与规划

产品定位

OpenCarb 是一个面向企业团队的 AI 助理平台，基于 OpenClaw 提供的 agent 能力，增加企业级的模型治理、技能治理、安全审计和团队协作控制面。 它不是个人生活助理，而是服务于企业内部的部门、项目组和工作组。

核心价值

  • 本地优先： 默认内网模型，降低数据外发风险。
  • 团队协作： 共享知识库、技能与审计策略。
  • 可控扩展： 技能与工具需经审计与审批。
  • 治理闭环： 完整的请求、执行与结果审计。

控制面实现栈

  • Backend：NestJS（`/api` 控制面）
  • Persistence：PostgreSQL + 文件化 SQL migrations
  • Queue/Cache：Redis（可用时入队）+ 内存 fallback
  • Jobs：并发、重试、死信、终止控制

执行面适配

  • Runtime Adapter：ACP createSession / invoke
  • 协议层：DTO、错误码映射、分层重试
  • 韧性：ACP 异常自动回退本地 stub
  • 审计：adapter/fallbackReason 结构化写入

可观测与交付

  • API：fallback stats / trend / alerts
  • Console：窗口、TopN、阈值告警视图
  • 验证：build / test / smoke / uat 自动化
  • 收口：关闭评审模板已生成并进入签收

V1 核心功能 (必做)

  • ✓ 工作区管理： 创建、成员管理、资源绑定。
  • ✓ 模型接入： 内网模型优先，受控外部 API 回退。
  • ✓ 知识索引： Git 仓库与文档库增量索引。
  • ✓ 技能治理： 基础启停、版本锁定、高风险审批。
  • ✓ 审计闭环： Prompt、工具、外发全链路记录。
  • ✓ 核心场景： 代码问答、新人 Onboarding、轻量 PR Review。

V1 明确不做

  • ✕ 跨团队知识共享市场
  • ✕ 多节点沙箱执行集群
  • ✕ Agent 自治编排平台
  • ✕ Graph DB 全局依赖图谱
  • ✕ 大规模第三方技能自由安装

技术实施策略

Implementation Decision

不是从头重做，也不是长期 fork 后深度魔改

OpenCarb 的推荐实施方式是：复用 OpenClaw 作为执行内核，独立建设 OpenCarb 的企业控制面。 这样既能利用 OpenClaw 已有的 runtime、ACP 和 skills 生态，也能把企业真正关心的工作区、权限、审计、 模型路由和技能治理掌握在自己的产品边界内。

路线 A
完全从零开发
自主可控，但成本最高，不适合当前阶段。
路线 B
长期 fork 后深改
前期快，但后续会严重拖累上游升级和产品边界。
推荐路线
独立主仓 + 复用内核
复用执行能力，外置企业控制面，最适合长期演进。
Core Principle
OpenClaw 负责执行
Runtime、ACP、skills 规范、session 执行和工具调度。
OpenCarb 负责裁决
工作区、RBAC、Policy Engine、Audit、Model Router、Knowledge Service。
中间用适配层解耦
Runtime Adapter、ACP Adapter、Approved Skill View、Tool Wrapper。

阶段性实施路径

Phase A
技术验证
用 clone/fork 快速验证 OpenClaw 的 runtime、ACP、skills 接入点，但不把临时 patch 变成长期主线。
Phase B
MVP 落地
OpenCarb 独立主仓，接入 Runtime Adapter、Model Router、Knowledge Service，跑通部门级最小闭环。
Phase C
企业化增强
引入通用审批、私有技能仓、标准化部署模板和更完整的多团队复制能力。

页面持续同步机制

后续开发中的同步规则

  • 阶段变更时： 同步更新路线图状态、开发进展表、下一步任务三处内容。
  • 主文档变更时： `PRD`、`V1 范围`、`架构`、`部署安全`、`路线图` 任一更新后，48 小时内同步页面关键文案。
  • 执行文档变更时： `OpenCarb-Phase1-Execution-Backlog.md` 更新后，同步刷新执行 Epic 状态与开发进展表。
  • 同步顺序固定： 先更新 md 主文档，再更新 `opencrabmvp.html`，最后做一次跨文档口径检查。

术语一致性约束

  • 统一主命名： 页面中统一使用 `Model Router`，避免和 `Model Proxy` 混用造成理解偏差。
  • 边界统一： 页面需始终保持“OpenCarb 负责控制面，OpenClaw 负责执行面”的表达。
  • 状态表达统一： 文档已完成不等于开发已启动，页面需分别展示“文档完成态”和“开发 readiness”。
