OpenCrab Whitepaper

为部门级与工作组级团队构建 可治理、可审计、可扩展 的 AI 助理平台

OpenCrab 基于 OpenClaw 的执行能力构建，但不把企业能力揉进底层 runtime。 它面向真实团队协作场景，优先解决工作区隔离、模型治理、知识检索、技能治理、安全审计与进度同步。

System Architecture

OpenCrab 的核心不是新的 Agent，而是企业控制面

OpenClaw 负责执行，OpenCrab 负责裁决。系统把身份、工作区、模型路由、知识检索、技能治理和审计策略统一收敛到控制面，避免企业版能力深度侵入上游 runtime。

Access Layer

入口统一，语义统一

V1 入口只保留三类：IDE 插件、Web 管理台、PR review webhook/bot。所有请求先落到 Session Gateway，补齐用户、工作区、仓库、上下文和策略快照后再进入执行链路。

V1 入口
IDE 插件、Web 管理台、PR webhook
后续入口
企业 IM 机器人、成员侧 Web 对话入口
Control Plane

企业能力全部外置

当前控制面已落地 NestJS 分层实现，关键能力覆盖 Workspace、Model Router、Knowledge/PR Jobs、Audit、Approval 与 Jobs Worker。 底层采用 PostgreSQL 持久化与 Redis 入队，支持失败重试、死信记录、runtime fallback 可观测统计。

统一身份与角色裁决
工作区隔离与资源绑定
模型路由与外发策略
审计闭环、fallback 结构化元数据与聚合统计
审批挂起、恢复/终止与作业状态流转
UAT 与关闭评审自动化脚本
Execution Plane

复用 OpenClaw 的执行内核

Runtime Adapter 已升级为 ACP 协议客户端模式：createSession / invoke 请求采用 DTO、错误码映射和分层重试。 当上游 ACP 不可达时自动回退到本地 stub，保证控制面主链路可用。

推荐实施原则
OpenClaw 负责执行，OpenCrab 负责裁决。运行时元数据（adapter/fallbackReason）已纳入审计事件，支持阈值告警与趋势追踪。
Knowledge & Model Layer

内网模型优先，知识由平台统一过滤

Knowledge Service 负责仓库、文档和 FAQ 的统一索引和权限过滤；Model Router 作为统一模型代理，负责在 Local LLM Gateway 与受控外部模型之间路由；高风险外发在 Policy Engine 中触发审批。

知识边界
runtime 不直连原始知识源，只获取已过滤结果。
模型边界
默认内网优先，外部模型必须显式配置并经策略控制。
可观测增强
已提供 fallback stats / trend / alerts 三类接口，并在 Web Console 提供窗口、TopN 与阈值视图。
Core Modules

V1 核心模块与非目标边界

V1 不追求全公司统一大脑，而是围绕单个工作区建立最小闭环：工作区、模型、知识、技能、审计与管理台。
Workspace
团队工作区
成员、角色、仓库、文档集、模型策略和技能集都围绕一个 workspace 管理。
Model
模型接入与路由
支持内网模型服务接入，外部模型作为受控回退通道，通过策略路由调用。
Knowledge
知识检索服务
Git 仓库、文档库、FAQ 增量索引，先做权限过滤，再向 runtime 提供可引用片段。
Skill
技能治理
兼容 OpenClaw 的 `SKILL.md` 规范，但企业启用、审批、版本锁定都由平台治理。
Audit
审计与策略
记录 prompt、工具、模型、文件访问和审批结果，形成可查询、可追责的审计链路。
Console
Web 管理台
用于工作区配置、模型接入、技能治理、审批处理和审计查看，而不是成员端通用聊天入口。
V1 核心场景
企业代码库问答与内部 API 调用指导
目标是降低历史代码理解成本，并显著减少内部接口调用的幻觉。
轻量 PR 评审与规范拦截
V1 先以 webhook/bot 跑通轻量闭环，不直接做完整平台化 review 流程。
新人 onboarding 与团队文档问答
围绕模块、目录结构、内部流程提问，并返回带来源的答案。
V1 明确不做
全公司统一知识大脑
多节点沙箱执行集群
复杂 Graph DB 和全量知识图谱
Agent 自治编排平台与行业定制化重工作流
Implementation Strategy

后续开发不是“从头做”，也不是“长期 fork 后深改”

推荐路线是：短期可基于 OpenClaw clone/fork 做技术验证，正式产品开发切换到独立 OpenCrab 主仓，复用 OpenClaw 作为执行内核，并把企业控制面全部外置。

Route A
从零重做

完全自主，但需要重做 runtime、session、skills、ACP 和工具链，成本过高，不利于首版交付。

Route B
长期 fork 深改

前期快，但企业控制面会和执行内核高度耦合，后续同步上游更新的成本会迅速升高。

Recommended
独立主仓 + 复用内核

OpenClaw 负责执行，OpenCrab 负责工作区、RBAC、Policy、Audit、Knowledge、Model Router 与 Skill Manager。

复用与自研边界
建议复用
  • OpenClaw Runtime
  • ACP Bridge
  • skills 规范与目录结构
  • 会话执行与 skill 调度基础逻辑
必须自研
  • Workspace / Identity / RBAC
  • Policy Engine / Audit Service
  • Knowledge Service
  • Skill Manager / Web Console
