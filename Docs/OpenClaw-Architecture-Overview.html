Executive Summary

个人、自托管的 AI 助理
Any OS. Any Platform. The lobster way.

愿景：在用户自有设备上运行、数据不出本地的个人 AI 助理。核心价值：本地优先、自有数据、多通道收件箱（WhatsApp/Telegram/Slack/Discord/WebChat 等）、技能生态（ClawHub）、Voice/Canvas/Nodes。产品即助理本身，Gateway 为控制面。

目标用户：个人与小团队、开发者与集成方。当前阶段：成熟开源（stable/beta/dev 频道，活跃贡献）。License：MIT。

GitHub openclaw.ai Docs Discord
与 OpenCrab 的关系

OpenCrab 复用 OpenClaw 的执行能力：session 生命周期、技能调度、工具执行、ACP 接入。企业所需的工作区、RBAC、审批、模型路由、审计等控制面由 OpenCrab 独立实现，通过 Runtime Adapter 与上游对接。

Value Proposition

产品定位与价值主张

核心能力、边界与替代方案对比。

核心能力矩阵
本地优先 Gateway 多通道收件箱 多 agent 路由 技能生态 ClawHub Voice / Canvas / Nodes 自有数据
本地优先

Gateway 跑在用户自己的设备或自建服务器上，会话与推理不依赖公有云助理服务。

自有数据

配置、会话、技能、凭证存放在本地（如 ~/.openclaw/），符合 own your data。

个人助理定位

目标用户是个人或小团队；多 agent 通过 workspace + session 做路由，非企业多租户/RBAC。

安全与沙箱

默认 main 在主机执行；非 main 可配置 Docker 沙箱；DM 采用 pairing/allowlist。

边界与对比

vs 公有云助理：数据主权、自托管。vs 纯本地无通道：多端接入。vs 企业多租户产品：个人/小团队优先。非：企业 RBAC/审批/审计、统一知识大脑（以官方表述为准）。

Technical Architecture

技术架构：Gateway 为控制面，Pi agent 为执行运行时

所有通道流量先进入 Gateway（WebSocket 控制面，默认 ws://127.0.0.1:18789），再分发到 Pi agent（RPC）、CLI、WebChat、macOS/iOS/Android 节点等。

上下文图（Context）
flowchart LR User[用户] Ch[通道 WhatsApp / Telegram / Slack ...] IDE[IDE ACP] Sys[OpenClaw Gateway + Pi agent] Model[模型服务] User --> Ch User --> IDE Ch --> Sys IDE --> Sys Sys --> Model

数据留在用户侧；模型可由用户自选内网或外部 API。

整体数据流
flowchart LR subgraph ch [Channels] In[WhatsApp / Telegram / Slack / Discord / WebChat ...] end subgraph gw [Gateway] WS[WebSocket Control Plane] end subgraph co [Consumers] Pi[Pi Agent RPC] CLI[CLI] UI[WebChat] App[macOS / iOS / Android] end In --> WS WS --> Pi WS --> CLI WS --> UI WS --> App
Gateway

单一 WebSocket 控制面，负责：sessions、presence、config、cron、webhooks、Control UI、Canvas host。Gateway 是连接所有客户端与 Pi agent 的枢纽，不直接执行业务逻辑。

Pi Agent

RPC 模式 agent 运行时，支持工具流式、块流式输出。负责 prompt 执行、skill 调度与底层工具调用，是「执行面」的核心。技能由 Pi agent 按 session 可见集合调度，Gateway 不直接执行业务逻辑。

Session 模型

main 为直连会话；群组/频道有独立 session 与隔离规则。支持激活模式（mention / always）、队列模式、回复策略（reply-back）。多 agent 通过 workspace + 每 agent 的 session 做路由。

ACP（Agent Client Protocol）

IDE 等客户端通过 stdio 上的 ACP 接入。session key 与 gateway session 映射，便于在 Cursor/VS Code 等环境中复用同一套会话与技能。

Skills & Skill Market

Skill 与 Skill 市场

技能是 OpenClaw 生态的核心扩展方式：目录式 SKILL.md 规范、多种来源与优先级、ClawHub 技能目录（市场）以及版本归档，共同构成「发现–安装–启用」的闭环。企业版可在此基础上做审批、私有仓与 Approved Skill View。

SKILL 规范要点
  • 目录与文件：技能以目录形式组织，每技能一个目录，内含 SKILL.md（及可选资源）。路径约定：skills/<skill-name>/SKILL.md，位于 workspace 根下或 bundled/managed 目录。
  • SKILL.md 内容：描述技能用途、适用场景、触发条件（when to use）、参数或约束等，供 agent 发现与调度；具体字段以 OpenClaw 官方文档为准，OpenCrab 兼容该格式且不修改基础结构。
  • 元数据与启用：OpenClaw 有 skill 元数据与「启用门槛」（gating）机制；企业侧可在不改写 SKILL.md 的前提下，通过平台元数据扩展（如 sourceType、approvalStatus、lockedVersion）做治理。

详见 openclaw 文档与仓库内 skills 示例。

技能来源与解析优先级
  • Bundled：随 OpenClaw 发行版内置，位于发行包内固定路径。
  • Managed：由平台或 ClawHub 托管，可更新、可发现。
  • Workspace：用户工作区目录（如 ~/.openclaw/workspace/skills/），本地或团队自定义。

优先级/覆盖：通常 workspace 可覆盖同名技能，其次 managed，再次 bundled；具体解析顺序以 OpenClaw 行为为准。

对 OpenCrab 的启示

平台以「Approved Skill View」为最终事实；建议解析顺序：工作区私有 > 平台托管官方 > 第三方受管导入。

ClawHub 技能目录（技能市场）

ClawHub 是 OpenClaw 的 Skill Directory（技能目录/市场），提供技能的发现、搜索与安装入口。

  • 启用 ClawHub 后，agent 可自动搜索并拉取所需技能；用户/管理员可通过 UI 或配置管理「从市场安装」的技能。
  • 安装与启用门槛（install gating）在 Control UI 中有体现，技能列表与启用状态可管理。
  • 企业版不直接依赖公有 ClawHub 作为唯一来源，而是自建「私有技能仓」+ 可选对接 ClawHub 或自托管镜像；审批、版本锁定、灰度由 OpenCrab Skill Manager 负责。
openclaw/clawhub clawhub.com
openclaw/skills 归档仓库

GitHub 上的 openclaw/skills 仓库归档 clawhub.com 上技能的全版本，便于离线使用、审计或自建镜像。

可视为 ClawHub 的「只读、版本化快照」，不替代 ClawHub 的发现与安装流程，但为企业侧做技能来源追溯、版本锁定提供参考。

对 OpenCrab 技能治理的启示
  • 复用：SKILL.md 格式、目录结构、调度与 gating 思路。
  • 企业增强：审批、私有技能仓、Approved Skill View、版本锁定与灰度、审计；生命周期与对象定义见本仓库 OpenCarb-Phase2-Skill-Governance-Spec.md（SkillPackage、ApprovedSkillView、导入–审核–发布–回滚）。

Product Logic

产品逻辑与用户旅程

首次使用（onboard）
  1. 安装：npm install -g openclaw 或从源码 pnpm build
  2. openclaw onboard --install-daemon
  3. 配置模型与通道（向导或配置文件）
  4. 首次对话（CLI 或 WebChat）

失败场景：未配置 token、通道未配对等；详见文档与 openclaw doctor。

消息与回复

用户从某通道发消息 → Gateway → Pi agent（session 可见技能/工具）→ 技能或工具调用 → 回复回通道。群组支持 mention/always 激活、队列与 reply-back。

会话状态

main 直连会话；群组/频道有独立 session。支持 /reset、/compact、/think 等命令；状态由 Gateway 持久化。
